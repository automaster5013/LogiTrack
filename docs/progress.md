# 구현 진행 현황

- 일괄 DLQ 재처리·폐기 계획 생성에 영속 `Idempotency-Key`와 동시 요청 잠금을 적용해 응답 유실 재시도가 기존 승인 객체를 반환하고, 같은 키의 다른 이벤트·사유·운영자 사용은 충돌로 거부합니다.
- 경고 정책 저장에 영속 `Idempotency-Key`를 적용해 성공 응답이 유실된 같은 요청은 완료 당시 정책이 유지되는 동안 기존 결과를 반환하고 UPSERT 감사를 중복 생성하지 않으며, 키의 다른 용도나 이후 정책이 바뀐 오래된 재시도는 충돌로 거부합니다.
- 경고 정책 이력 복원의 원본 audit ID와 운영자를 불변 RESTORE 감사에 고정해 응답 유실 뒤 동일 복원을 재시도하면 현재 결과를 반환하고 감사를 중복 생성하지 않으며, 이후 정책이 바뀐 오래된 재시도는 충돌로 거부합니다.
- 차량별 경고 정책 reset의 성공 응답이 유실된 뒤 같은 운영자가 재시도하면 현재 비활성 정책을 성공으로 반환하고 RESET 감사를 중복 기록하지 않으며, 다른 운영자의 후속 reset은 충돌로 거부합니다.
- 일괄 DLQ 재처리·폐기 계획 실행의 성공 응답이 유실된 뒤 원래 운영자가 같은 승인을 다시 보내면 저장된 완료·부분 완료·만료 결과를 반환하고 이벤트 작업을 중복 실행하지 않습니다.
- DLQ 재처리 또는 영구 폐기의 성공 응답이 유실된 뒤 동일 요청을 다시 보내면 기존 완료 상태를 성공으로 반환하고, Kafka 발행·감사 이력·메트릭을 중복 생성하지 않으며 서로 다른 폐기 의도는 계속 거부합니다.
- Outbox 재발행 요청의 응답이 유실된 뒤 같은 이벤트를 다시 요청해도 이미 `PENDING` 또는 `PUBLISHED`이면 현재 상태를 성공으로 반환하고 감사 이력·재시도 메트릭을 중복 기록하지 않습니다.
- 주문 생성·배차와 창고 입고·피킹·출고가 불확실하게 실패하면 멱등성 식별자뿐 아니라 동일 trace ID도 성공 확인까지 재사용해 서버 감사 이벤트와 클라이언트 재시도를 하나의 운영 의도로 추적합니다.
- 경고 확인 요청이 불확실하게 실패하면 경고별 trace ID를 성공 응답이나 실시간 확인 이벤트까지 재사용해 하나의 운영 의도가 재시도마다 서로 다른 추적으로 분산되지 않도록 합니다.
- 창고 입고·출고 참조번호를 짧은 시각 접미사 대신 80비트 UUID 접미사로 발급해 대규모 누적 운영에서도 업무 참조 충돌 확률을 실질적으로 제거하면서, 실패 재시도에는 동일 참조번호를 유지합니다.
- 새 주문 번호를 짧은 시각 접미사 대신 80비트 UUID 접미사로 발급해 대규모 누적 운영에서도 번호 충돌 확률을 실질적으로 제거하면서, 실패 재시도에는 동일 번호를 유지합니다.
- 주문 배차 요청의 응답이 불확실하게 실패하면 주문별 차량 배정과 idempotency key를 성공 확인까지 재사용하고, 성공 뒤 다음 독립 배차에서만 새 식별자를 발급해 재시도의 중복 배송 생성을 방지합니다.
- 주문 생성 요청의 응답이 불확실하게 실패하면 같은 주문 번호와 idempotency key를 성공 확인까지 재사용하고, 성공 뒤 다음 독립 주문에서만 새 식별자를 발급해 네트워크 복구 재시도의 중복 주문 생성을 방지합니다.
- 창고 피킹 요청의 응답이 불확실하게 실패하면 같은 참조번호와 idempotency key를 피킹 성공 확인까지 재사용하고, 다음 독립 출고에서만 새 식별자를 발급해 재시도의 중복 재고 예약을 방지합니다.
- 창고 입고 요청의 응답이 불확실하게 실패하면 같은 참조번호와 idempotency key를 성공 확인까지 재사용하고, 성공 뒤 다음 작업에서만 새 식별자를 발급해 네트워크 복구 재시도의 중복 재고 반영을 방지합니다.
- 창고 출고의 피킹 성공 직후 연결이 끊기면 후속 출고 요청을 보류하고 생성된 피킹 작업을 재시도 대상으로 보존해 실패가 확실한 요청과 잘못된 출고 오류를 예방합니다.
- DLQ 재처리·영구 폐기와 Outbox 재발행의 확인 대화상자가 열린 사이 연결이 끊겨도 실제 변경 요청 직전에 네트워크를 다시 검증해 실패 요청과 잘못된 복구 오류를 예방합니다.
- 브라우저 오프라인 중에는 검색·범위 변경으로 새로 노출된 차량의 지도 경로·위치 스냅샷 조회를 보류하고 온라인 복귀 즉시 필요한 차량만 불러와 실패 요청과 잘못된 지도 오류를 예방합니다.
- 브라우저 오프라인 중에는 복구 큐의 이전 이벤트 추가 조회를 연결 대기 상태로 중단하고 실행 함수도 네트워크를 재검증해 불필요한 실패 요청과 오해를 부르는 복구 오류를 예방합니다.
- 브라우저 오프라인 중에는 배포 버전 확인 요청과 타이머를 중단하고 온라인 복귀 즉시 버전을 다시 확인해 실패가 확실한 주기 요청을 없애면서 새 배포 자동 갱신은 유지합니다.
- 브라우저 오프라인 전환 시 실시간 EventSource 연결을 닫아 브라우저의 무의미한 자동 재연결을 중단하고, 온라인 복귀 시 스트림을 다시 열면서 스냅샷은 정확히 한 번 동기화합니다.
- 브라우저 오프라인 중에는 작업공간별 주기 동기화를 중단해 실패가 확실한 반복 요청과 잘못된 연결 오류 누적을 막고, 온라인 복귀 즉시 현재 작업공간 데이터를 다시 동기화합니다.
- 브라우저 오프라인 중에는 DLQ 재처리·단건/일괄 폐기와 Outbox 재발행을 연결 대기 상태로 비활성화하고 실행 함수도 네트워크 상태를 재검증해 실패가 확실한 복구 변경과 잘못된 감사 오류를 예방합니다.
- 브라우저 오프라인 중에는 경고 정책 저장·기본값 전환·이력 복원을 연결 대기 상태로 비활성화하고 공통 실행 잠금도 네트워크 상태를 재검증해 실패 설정과 오해를 부르는 감사 오류를 예방합니다.
- 브라우저 오프라인 중에는 배송 경고 확인 버튼을 연결 대기 상태로 비활성화하고 확인 실행 함수도 네트워크 상태를 재검증해 실패가 확실한 운영 감사 요청과 잘못된 오류 알림을 예방합니다.
- 지도 스타일과 운영 레이어 설정이 완료되는 `load` 시점에 준비 상태를 확정해 후속 렌더 변화가 없는 복구에서도 불필요한 `idle` 대기로 지도가 비활성 상태에 머무르지 않습니다.
- 브라우저 오프라인 중에는 주문별 차량 배차 버튼을 연결 대기 상태로 비활성화하고 배차 실행 함수도 네트워크 상태를 재검증해 실패 배차와 불필요한 운영 오류를 예방합니다.
- 브라우저 오프라인 중에는 창고 입고·피킹/출고 버튼을 연결 대기 상태로 비활성화하고 공통 실행 잠금도 네트워크 상태를 재검증해 중복 재고 오류와 실패가 확실한 변경 요청을 예방합니다.
- 브라우저 오프라인 중에는 상황판·주문 작업공간의 새 주문 버튼을 연결 대기 상태로 비활성화하고 생성 함수도 네트워크 상태를 재검증해 실패 주문과 오해를 부르는 오류 알림을 예방합니다.
- 브라우저 오프라인 중에는 작업공간 새로고침과 오류 재시도를 연결 대기 상태로 비활성화하고 실행 함수도 네트워크 상태를 재검증해 실패가 확실한 중복 API 요청을 차단합니다.
- 상단 실시간 스트림 상태와 복구 안내가 브라우저 오프라인을 즉시 구분해 마지막 동기화 데이터임을 알리고 수동 데이터 확인을 비활성화하며, 온라인 복귀 후 자동 재동기화 상태로 돌아갑니다.
- 지도 자동 복구의 각 지수 백오프 구간에 ±20% 지터를 적용하고 60초 상한은 유지해 다수 운영자 브라우저가 장애 복구 시점에 외부 지도 서비스를 동시에 재호출하는 집중 부하를 분산합니다.
- 브라우저가 오프라인인 동안 지도 수동 재시도를 연결 대기 상태로 비활성화해 실패가 보장된 요청과 불필요한 백오프 증가를 막고, 온라인 복귀 이벤트가 복구를 전담합니다.
- 지도 오류 패널이 브라우저의 온라인·오프라인 전환을 실시간 반영해 오프라인에서는 잘못된 자동 재시도 시각 대신 연결 대기 상태와 배송 데이터 화면 유지 여부를 명확히 안내합니다.
- 지도 자동 복구 대기 중 브라우저가 오프라인으로 바뀌면 예약된 요청을 건너뛰고, 연결 복귀 시 지도만 즉시 한 번 재시도해 무의미한 실패와 백오프 증가를 막습니다.
- 지도 스타일·타일 장애가 지속되면 자동 복구 간격을 5초부터 최대 60초까지 지수 백오프로 늘리고, 복구 성공 시 즉시 초기화해 외부 지도 서비스와 브라우저에 반복 부하를 주지 않습니다.
- 브라우저가 이미 온라인인 상태에서 지도 스타일·타일의 일시적 연결 실패가 발생해도 짧은 지연 뒤 지도만 자동 재시도하고, 차량 검색·선택·입력 포커스와 데이터 스트림을 그대로 유지합니다.
- 온라인 복귀에 따른 자동 지도 복구는 현재 검색·조작 포커스를 그대로 유지하고, 운영자가 오류 패널에서 직접 재시도한 경우에만 복구된 지도 캔버스로 포커스를 넘겨 비동기 복구가 입력을 가로채지 않도록 합니다.
- 지도 초기 연결 실패 뒤 브라우저가 온라인으로 복귀하면 운영자 입력 없이 지도만 자동 재시도하고, 동기 잠금으로 중복 `online` 신호의 복수 인스턴스 생성을 차단하면서 검색·선택·포커스를 보존합니다.
- 지도 단독 재시도 중 오류 패널과 비활성 진행 버튼을 유지해 중복 요청을 막고, 복구 완료 후 지도 캔버스로 포커스를 넘겨 키보드 사용자의 조작 맥락이 문서 본문으로 유실되지 않도록 합니다.
- 지도 스타일·타일 초기 연결 실패 시 전체 관제 화면을 새로고침하지 않고 지도 인스턴스만 재생성해 차량 검색·범위·선택과 실시간 운영 맥락을 보존하며 복구합니다.
- 확대 지도가 열린 동안 DOM 계층의 모든 배경 분기를 `inert`와 `aria-hidden`으로 격리하고 닫을 때 기존 상태를 복원해 포인터·키보드·보조기술 탐색이 modal 밖 관제 화면에 닿지 않도록 합니다.
- OS의 동작 줄이기 설정이 활성화되면 차량 선택·전체 차량 맞춤 지도의 900ms 이동 애니메이션도 즉시 전환으로 바꿔 CSS 전환과 지도 카메라가 동일한 모션 접근성 계약을 따르도록 합니다.
- 확대 지도를 접근 가능한 modal dialog로 선언하고 진입 포커스·Tab 순환·ESC 종료·원래 조작으로의 포커스 복귀를 보장해 키보드 사용자가 배경 화면으로 이탈하지 않도록 합니다.
- 1080px를 넘는 대형 데스크톱·QHD 화면에서도 지도 높이 상한이 viewport 잔여 공간을 조기에 제한하지 않도록 확장하고 1920×1200·2560×1440 첫 화면 채움 상태를 Chromium으로 회귀 검증합니다.
- 다섯 운영 메뉴의 상단 여백을 메뉴별 핵심 상태·대표 작업·동기화 도구를 결합한 공통 command center로 재구성하고, 카드 내부 중복 작업과 안내를 제거하면서 좁은 화면의 지도 우선 표시를 유지합니다.
- 프로덕션 cutover 최종 완료 게이트를 서울 21개·버지니아 3개 CloudWatch 경보의 존재와 연속 10분 `OK` 상태에 결속해 경보 발화·데이터 부족·누락·최근 전환 중에는 완료 receipt 생성을 차단합니다.
